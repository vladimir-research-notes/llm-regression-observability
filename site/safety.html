Safety and privacy

This is a reliability/evaluation framework — not a medical, legal, or security authority. It makes no safety certification of any model or application. Full text in docs/SAFETY.md.

Data scope

  • All fixtures are synthetic — prompts, outputs, tool traces, retrieval docs are authored for this repo. No real user data anywhere.
  • Small and safe — any biomedical- or security-adjacent example is non-clinical, non-actionable, and non-exploitative; it exists only to exercise the refusal and evidence scorers.
  • The refusal/boundary suite uses prompts whose expected behavior is stable and benign; it tests whether a change shifts refusal behavior, not whether a model should comply with anything harmful.

Redaction: the mask and the gate

status: Milestone 9 complete — 12 rules in two tiers; redaction runs before the executor hashes a run, before the report renders, and before the span writer writes; 52/52 committed fixture records pass through unchanged; 73 tests

Two mechanisms, one pattern table. traces/redaction.py is the single definition of "credential-like" in this repository; the report gate, llmreg validate-fixtures, the span writer and the trace writer all read it from there. A second copy of a pattern table is a false sense of safety, because the copy that misses a pattern is the one that runs.

The mask. redact_text() replaces a match with [REDACTED:<rule>]. It runs on every content field of a RunRecord inside execute_suite — before tokens are accounted and before run.jsonl is hashed, so records_sha256 digests the redacted bytes — and on every free-text field the report generator copies out of a comparison artifact. The placeholder matches no rule, so redaction is idempotent.

The gate. assert_redaction_clean scans the fully rendered report immediately before the bytes hit the disk, and is fail-closed: a credential-like string that reached the document means the report is refused, not written. The error names the pattern and the line and never echoes the value — an error message is a place secrets leak too. llmreg report --dry-run runs the same gate, so a dry run cannot pass where a real write would refuse. write_spans gates spans.jsonl the same way.

The two are not redundant. The mask sees only free text, because identifiers — case ids, run ids, metric names, tool names — are join keys, and rewriting one would corrupt the artifact it claims to protect. The gate reads the whole document, identifiers included. A secret in an explanation is masked; a secret in a run id is refused.

Two tiers: refuse on evidence, mask on suspicion

TierRulesBehavior
certain provider key prefixes (sk-…, AKIA…, gh[pousr]_…, AIza…, xox[baprs]-…), JWT, private-key header, Bearer …, Authorization: … mask, and refuse an artifact that still contains one
heuristic credential-named assignment (api_key=…), email address, generic high-entropy token mask only — never blocks an artifact

A heuristic rule can fire on legitimate text, and a false-positive refusal is a denial of service on your own report. A false-positive mask costs one mangled string, and redaction_status records that it happened. The generic-token rule additionally requires 24+ characters, mixed character classes, and entropy above a prose floor — the character-class filter, not the entropy floor, is what keeps it off the SHA-256 digest this project writes into every run_meta.json.

redaction_status

Derived by the redactor, never believed from an adapter. The values form a lattice — clean < redacted < flagged — and redaction takes the maximum of what it found and what the record already claimed, so the status can only escalate and redacting twice changes nothing.

  • clean — no rule fired.
  • redacted — a rule fired in a content field and was masked.
  • flagged — a certain-tier rule fired in an identity field (a join key the redactor will not rewrite). The executor refuses the run, naming the field and the pattern. A flagged record therefore never appears in a file this project wrote; it is reachable only on a trace imported from elsewhere.

Independently of all of this: a comparison artifact carries no model-generated prose to begin with. Flag explanations, per-case summaries and cluster labels are authored by the rules from metric names, numbers, tool names and property names — never by copying a model's output. The report renders only those, so the gate is a backstop, not the only line of defence.

Never committed

Secrets, API keys, real API responses, private data, .env files, large logs, response caches, model weights, and .claude/settings*.json are all git-ignored. The repository-hygiene check scans the committed tree for what slipped through anyway:

python3 scripts/08_check_repo_hygiene.py   # exits 1 on any finding
llmreg scan-secrets [PATH]                # the same scan, from the CLI

It applies the certain tier only. The heuristic tier would flag every SHA-256 digest in docs/ and every author email in pyproject.toml, and a hygiene check that cries wolf is a hygiene check that gets skipped. A file that must legitimately name a credential shape — a test asserting the scanner works — marks the line with redaction:allow. The scan reports the file, the line and the pattern name, never the matched value. It reports 0 findings on this repository.

Optional paid-API mode

No paid API is used by default or in any test. If the optional API adapter is enabled (Milestone 11) it is gated by dry-run mode, a token/cost estimator, a hard max-cost guard, a response cache, and explicit opt-in. Real API responses are never committed.

Honest framing

Where a metric is approximate (cost estimation) or a placeholder (explanation quality), the docs and code say so. The system measures relative behavioral change on synthetic fixtures; it does not validate correctness, safety, or fitness for any real-world use.
