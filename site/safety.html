Safety and privacy

This is a reliability/evaluation framework — not a medical, legal, or security authority. It makes no safety certification of any model or application. Full text in docs/SAFETY.md.

Data scope

  • All fixtures are synthetic — prompts, outputs, tool traces, retrieval docs are authored for this repo. No real user data anywhere.
  • Small and safe — any biomedical- or security-adjacent example is non-clinical, non-actionable, and non-exploitative; it exists only to exercise the refusal and evidence scorers.
  • The refusal/boundary suite uses prompts whose expected behavior is stable and benign; it tests whether a change shifts refusal behavior, not whether a model should comply with anything harmful.

Redaction: the gate (Milestone 7) and the mask (Milestone 9)

Two mechanisms, built in that order on purpose.

The gate exists now. reports/base.py::assert_redaction_clean scans the fully rendered report immediately before the bytes hit the disk, and is fail-closed: a credential-like string that reached the document means the report is refused, not written. The error names the pattern and the line and never echoes the value — an error message is a place secrets leak too. llmreg report --dry-run runs the same gate, so a dry run cannot pass where a real write would refuse. The patterns it recognizes today (shared with llmreg validate-fixtures) are provider-style API keys, bearer tokens, and private-key headers.

The mask arrives with Milestone 9. traces/redaction.py will supply a redactor that masks rather than refuses — the patterns above plus generic high-entropy tokens, Authorization headers and email addresses — and will set redaction_status (clean / redacted / flagged) on each RunRecord before persistence. It plugs into the Redactor seam that reports.build_report() already takes; the gate stays exactly where it is, as the last assertion. Milestone 7's default redactor masks nothing, which is precisely why the gate is fail-closed rather than advisory.

Independently of both: a comparison artifact carries no model-generated prose to begin with. Flag explanations, per-case summaries and cluster labels are authored by the rules from metric names, numbers, tool names and property names — never by copying a model's output. The report renders only those, so the gate is a backstop, not the only line of defence.

Never committed

Secrets, API keys, real API responses, private data, .env files, large logs, response caches, model weights, and .claude/settings*.json are all git-ignored, and a repository-hygiene check scans for them.

Optional paid-API mode

No paid API is used by default or in any test. If the optional API adapter is enabled (Milestone 11) it is gated by dry-run mode, a token/cost estimator, a hard max-cost guard, a response cache, and explicit opt-in. Real API responses are never committed.

Honest framing

Where a metric is approximate (cost estimation) or a placeholder (explanation quality), the docs and code say so. The system measures relative behavioral change on synthetic fixtures; it does not validate correctness, safety, or fitness for any real-world use.
