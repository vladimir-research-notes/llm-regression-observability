Safety and privacy

This is a reliability/evaluation framework — not a medical, legal, or security authority. It makes no safety certification of any model or application. Full text in docs/SAFETY.md.

Data scope

  • All fixtures are synthetic — prompts, outputs, tool traces, retrieval docs are authored for this repo. No real user data anywhere.
  • Small and safe — any biomedical- or security-adjacent example is non-clinical, non-actionable, and non-exploitative; it exists only to exercise the refusal and evidence scorers.
  • The refusal/boundary suite uses prompts whose expected behavior is stable and benign; it tests whether a change shifts refusal behavior, not whether a model should comply with anything harmful.

Redaction (Milestone 9)

Before any trace or report is written, text passes through a redactor that masks fake API keys, generic secrets / high-entropy tokens, bearer tokens and Authorization headers, email addresses, and other obvious credential-like strings. Redaction is covered by tests and runs before report generation; redaction_status records whether a record was clean, redacted, or flagged.

Never committed

Secrets, API keys, real API responses, private data, .env files, large logs, response caches, model weights, and .claude/settings*.json are all git-ignored, and a repository-hygiene check scans for them.

Optional paid-API mode

No paid API is used by default or in any test. If the optional API adapter is enabled (Milestone 11) it is gated by dry-run mode, a token/cost estimator, a hard max-cost guard, a response cache, and explicit opt-in. Real API responses are never committed.

Honest framing

Where a metric is approximate (cost estimation) or a placeholder (explanation quality), the docs and code say so. The system measures relative behavioral change on synthetic fixtures; it does not validate correctness, safety, or fitness for any real-world use.
