Limitations and non-goals

Being explicit about what this project does not do is part of the quality bar. Full text in docs/LIMITATIONS.md.

Synthetic fixtures

All cases are small and synthetic, designed to exercise each scorer and to carry known, injected regressions so the detector can be tested against ground truth. They are not a representative sample of any real workload; results on them do not generalize to production traffic.

No universal model evaluation

This is not a benchmark or a leaderboard. It measures relative behavioral change between a baseline and a candidate on a fixed suite. It does not rank models or certify that a model is good, safe, or correct.

Deterministic mocks, not live models

The default path uses mock / recorded / scripted adapters — reproducible and free, but tested against recorded behavior, not live stochasticity. Handling live-model variance (multiple samples, significance tests) is a documented future direction, not a current claim.

Estimated, not measured, cost

Token counts use a transparent char-based estimator and a fixture price table. Costs are estimates for relative comparison, not bills.

Placeholder scorers

Explanation-quality and semantic similarity (semantic_stub) are deterministic stand-ins, not learned judges. They are labeled as placeholders in code and docs.

Heuristic attribution

The application-vs-infrastructure split is rule-based and conservative. It reduces harness-noise false positives but can misattribute an unusual failure; it reports its confidence rather than claiming certainty.

No production deployment

No server, no auth, no multi-tenant story, no persistence beyond local files (optional SQLite index is regenerable). This is a local-first research/engineering tool — and not a medical, legal, or security authority (see Safety).
