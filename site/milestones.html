llm-regression-observability
A CPU-first framework for detecting, explaining, and reporting regressions in LLM applications and agentic systems.

Milestones

The system is built in fourteen milestones (0–13), one commit each. Each is implemented by a single claude -p run driven by scripts/run_all_milestones_with_claude.sh, which stops on agent failure, no new commit, a dirty tree, or a failing test. Full specs live in docs/milestones/.

status: contract & harness ready; milestones not yet started

  1. Scaffold & project contract
    Package skeleton, pyproject.toml, llmreg CLI stub, first CPU-only tests. Dependency-free core.
  2. Core schemas & trace model
    Typed contracts — EvalCase, RunRecord, ToolCallTrace, RetrievalTrace, MetricResult, ComparisonRecord, RegressionFlag, ReportSummary — with byte-stable serialization and round-trip tests.
  3. Fixture suites
    Six synthetic suites (structured JSON, tool use, retrieval/evidence, refusal boundary, latency/cost, agent trace), each with baseline + candidate defects annotated by expected category, plus a fixture validator.
  4. Adapters
    MockModelAdapter, RecordedModelAdapter, ScriptedRegressionAdapter (injects known regressions), and an inert ApiAdapterStub. All deterministic.
  5. Run-suite executor
    Read cases → call adapter → record outputs, tool calls, retrieval, token/cost estimates, latency → write reproducible results/runs/ traces.
  6. Evaluators
    Deterministic scorers for exact/structural success, JSON schema validity, tool-call drift, evidence coverage, refusal shift, latency/cost, error classification, trace completeness — tested with exact expected scores.
  7. Baseline vs candidate comparison
    Pair cases, compute deltas, raise regression flags with severity and app/infra attribution, cluster failures, aggregate by suite and category. Detects the injected regressions.
  8. Reports
    Markdown (+ optional HTML): headline, per-category changes, worst regressions, examples, latency/cost tables, validity table, tool-call and evidence diffs, limitations. Redaction-gated.
  9. Observability layer
    Request / model-call / tool-call / retrieval / evaluator spans and aggregate metrics. Trace completeness and infra signals reported separately from application scores.
  10. Redaction & safety hygiene
    Mask fake API keys, secrets, bearer tokens, emails, credential-like strings — before any report is generated. Proven by tests.
  11. Integration contracts
    Trace import/export formats for a code-agent runtime, BioAgentBench, BioScientist OS, agent-control-bench, and optional Claude API — validated on synthetic examples only; no external repo required.
  12. Optional API adapter stub & cost guard
    Disabled by default: dry-run mode, token/cost estimator, hard max-cost guard, response cache, explicit opt-in. No real API in any test.
  13. Final portfolio report
    README, docs/RESULTS.md, and website brought to portfolio quality with real, reproducible smoke-run numbers.
  14. Final cleanup
    Run every quality gate end to end; verify no secrets/large logs/caches; leave a clean working tree. Nothing pushed.

How a milestone runs

./scripts/run_all_milestones_with_claude.sh        # milestones 0..13
./scripts/run_all_milestones_with_claude.sh 4 6    # a subrange

Each run reads CLAUDE.md, the plan, and the milestone spec; implements exactly one milestone; updates docs and this website; writes a human-review placeholder; and commits locally.
