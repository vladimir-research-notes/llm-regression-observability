llm-regression-observability
A CPU-first framework for detecting, explaining, and reporting regressions in LLM applications and agentic systems.

Milestones

The system is built in fourteen milestones (0–13), one commit each. Each is implemented by a single claude -p run driven by scripts/run_all_milestones_with_claude.sh, which stops on agent failure, no new commit, a dirty tree, or a failing test. Full specs live in docs/milestones/.

  1. Scaffold & project contract complete
    Package skeleton, pyproject.toml (dependency-free core), llmreg CLI (version, check-env) with a python3 -m entry, a conftest.py path shim, and 14 CPU-only tests (test_smoke.py, test_scaffold_layout.py). The layout test enforces the empty runtime-dependency list.
  2. Core schemas & trace model complete
    Typed contracts — EvalCase, EvalSuite, RunRecord (alias ModelTrace), ToolCallTrace, RetrievalTrace, RetrievalDoc, ErrorRecord, MetricResult, ComparisonRecord, RegressionFlag, ReportSummary, FailureCluster — as stdlib dataclasses in schemas.py. Annotation-driven validation (missing/unknown field, wrong type, enum vocab, int→float coercion) raising SchemaError; byte-stable to_json() with sorted keys; 54 round-trip/rejection/stability tests.
  3. Fixture suites complete
    Six synthetic suites (structured JSON, tool use, retrieval/evidence, refusal boundary, latency/cost, agent trace) — 26 cases: 18 injected defects + 8 negative controls. Cases (EvalCase) and per-case ground truth (CaseExpectation) live under evals/fixtures/; recorded baseline/candidate RunRecords under data/fixtures/. A stdlib-only restricted-YAML reader parses evals/suites/smoke.yaml. The validator (llmreg validate-fixtures / scripts/01_validate_fixtures.py) checks schemas, referential integrity, that each injected defect actually differs from its baseline, manifest resolution, and a credential-like-string safety scan. 25 fixture tests.
  4. Adapters complete
    Four deterministic adapters in adapters/. AdapterContext (run identity: app_version, model/prompt/tool versions, recorded timestamp) is kept separate from AdapterResponse (behavior: output, tool calls, retrieval, errors, tokens/latency/cost); build_run_record() joins them, so no scored path ever reads the clock. RecordedModelAdapter replays all 52 committed fixture records byte for byte. ScriptedRegressionAdapter applies one of 15 pure injectors (invalid JSON, dropped/wrong/extra tool, arg drift, order swap, unsupported claim, dropped citation, refusal flip, added latency/cost, injected error) to a clean baseline; its plan is derived from the Milestone 2 CaseExpectation ground truth, so non-controls get a defect of their annotated category, infra-attributed cases get an infra-origin error, and true controls are left untouched. ApiAdapterStub raises when disabled, which is the default — no default path reaches a paid API. (Milestone 11 built the guarded ladder out behind that same opt-in; see Cost guard.) 46 adapter tests.
  5. Run-suite executor complete
    llmreg run-suite (in executor.py) resolves a suite manifest into an ordered EvalSuite, drives an adapter over every case, and writes results/runs/<run_id>/run.jsonl plus a run_meta.json sidecar (identity, totals, cost model, SHA-256 of the records). Three decisions the spec left open are settled here. The executor owns run identity: it re-stamps run_id and app_version onto every replayed record — so (run_id, case_id) keys the artifact — while model_id, prompt/tool versions, and timestamp stay as the adapter reported them unless explicitly overridden. Latency is recorded, never measured: timing the adapter would put an ambient value into a scored field. Tokens and cost are derived only where the adapter left zeros, and run_meta.json counts how many records took that path, so no artifact hides which numbers were invented. Byte-stable persistence (sorted keys, compact JSONL, explicit UTF-8 and \n) lives in one place, traces/storage.py. 51 executor tests, including an AST scan that fails if the new modules import time, datetime, random, or anything network-shaped.
  6. Evaluators complete
    Ten deterministic scorer modules in evaluators/, each a pure function of (EvalCase, RunRecord): structural task_success (opt-in exact_match), JSON parse/schema validity and field diff (against a stdlib JSON Schema subset — no jsonschema dependency), tool-call drift (allowed-tool ratio, order-sensitive sequence similarity, missing/extra tools, argument distance), evidence grounding (citation presence/correctness, coverage, unsupported claims), refusal shift and risk-label drift, recorded latency with type-7 p50/p95, cost, error classification, and trace completeness. Three decisions carry the design. A metric that cannot be computed is not emitted — an absent metric means not applicable, never zero, so field_diff_count stays silent when the output did not parse and one defect never counts twice. Direction lives in a table (METRIC_DIRECTION), and NEVER_FLAG_METRICS guarantees the two placeholders (semantic_similarity_stub, explanation quality) and the infra counters can never raise a regression. Trace completeness is a harness signal, not an application score: a broken JSON output is a regression with a complete trace, while a record with no latency is an incomplete trace — which is what lets Milestone 6 exclude harness failures instead of scoring their zeros. 155 tests assert exact expected scores for all 26 fixture cases × both sides; the eighteen injected defects each move exactly the metric they target, and an AST scan fails if any of the thirteen modules imports time, datetime, random, or anything network-shaped.
  7. Baseline vs candidate comparison complete
    The heart of the system. llmreg compare loads two runs, pairs them by case_id (a case present on one side only is reported unpaired, never scored as a success), diffs the behavioral fields, and applies eight threshold rules read from the suite manifest. Detection on ground truth: 18 of 18 injected defects, with the category and severity each fixture's expected.json annotates; 0 false positives on the 8 negative controls. Three decisions carry the design. One defect, one signal — task_success is the union of a case's declared properties, most of which another dimension already owns, so a task-success drop is attributed (PROPERTY_CATEGORY) and final_answer_regression fires only on an answer-level property; without it all 18 defects would report twice. A new unsupported claim is critical; a claim that lost its support is a warning — both raise unsupported_claim_count 0→1, so the rule compares claim texts to tell an invented fact from degraded grounding. Harness noise is withheld, not dropped — when every error on a candidate record is origin=infra, its flags are suppressed and written to comparison_meta.json, which is research question 9 and a documented masking risk. Failures cluster by (category, signature) — disallowed_tool:shell_exec, not "a tool was wrong" — with no fitted distance metric, because a fitted grouping could not be reproduced from the artifact. Latency and cost each need a relative and an absolute floor. 96 tests; two comparisons of the same runs are byte-identical.
  8. Reports complete
    The product's surface. llmreg report renders a comparison as Markdown and as one self-contained HTML file: verdict and provenance, per-category changes, worst regressions, a worked example each for structured output / tool-call diff / evidence grounding, structured-output validity, latency and cost tables, failure clusters, thresholds applied, and a limitations note. Four decisions carry it. The report reads the artifacts and nothing else — comparison.jsonl, summary.json, comparison_meta.json — so it is reproducible from a directory a colleague hands you and cannot quietly enrich itself from a source the reader lacks; the visible cost is that the structured-output table shows a delta (-1) rather than the two absolute validity values, which no artifact records. Selection happens once, in a shared ReportModel: the renderers lay out tables, they do not choose rows, so Markdown and HTML can never disagree about which regression is worst. Redaction is a fail-closed gate, not yet a mask — the fully rendered document is scanned for credential-like strings immediately before the bytes hit the disk, and one that survived the redactor seam is refused, not written; the error names the pattern and the line but never echoes the value, and --dry-run runs the same gate so it cannot pass where a write would refuse. Milestone 9's masking redactor plugs into that seam and the gate stays put. The silences get their own section — "what the engine declined to say" prints unpaired cases, infra-attributed cases and withheld flags, because a clean headline over a comparison that could only look at half its cases is the failure mode this project exists to avoid. Sub-threshold latency and cost moves are rows too, so a working tolerance is visible rather than implied. No clock, no RNG, and no generation timestamp: two reports of one comparison are byte-identical, and a committed sample in docs/examples/ is regenerated by a test so it cannot go stale. 67 tests.
  9. Observability layer complete
    What makes the application-vs-harness distinction operational. llmreg aggregate projects each run into a nested, OpenTelemetry-shaped span tree (request → model_call / tool_call / retrieval / evaluator, no OpenTelemetry dependency) and reduces its per-case MetricResults to suite numbers, writing results/runs/<run_id>/spans.jsonl and results/processed/<run_id>/aggregate.json. Four decisions carry it. Spans are derived, not emitted — nothing here instruments a live call, because there is no live call; the projection is a pure function of (case, record, metrics), so the tree is rebuildable and byte-identical, and span ids are content-addressed (sha256(run_id | case_id | path)) rather than random. That is also why the stage holding both the trace and the scores owns the file: an evaluator span needs a metric, and the executor has never scored anything. Only one duration was ever recorded. The trace carries latency_ms and nothing else, so the request span's interval is recorded, its application children get a contiguous partition of that interval in trace order (derived — which asserts ordering, not duration: a child's width is latency_ms / step_count and means nothing alone), and evaluator spans are zero-width at the request's end (none) because scoring happens afterwards, in the harness. Inventing per-step durations was the easy lie available here; labelling every span with its timing source was done instead. Spans carry symbols, never free text — a tool name, a source id, a metric name, an error kind, argument keys, counts, statuses; never a prompt, an output, a tool argument value, a snippet, or an error message, because Milestone 9's redactor has not run and until it has, no telemetry artifact may copy a string. A test scans every attribute of all 52 committed fixture records against the free text of the record it came from. The suite summary keeps three maps, not one: application_metrics, harness_metrics (trace_completeness, infra_error_rate, incomplete_trace_rate) and placeholder_metrics. A flat map lets a broken exporter and a broken model look alike at a glance, so the separation is structural rather than a naming convention. On the smoke candidate, at_more_retries moves error_rate to 0.125 and at_infra_noise moves infra_error_rate to 0.125 — two errored cases, two different maps. Reducers are named (ratio counts cases, mean counts events), direction is inherited from METRIC_DIRECTION rather than restated, and metric_coverage says how many cases answered each number. validate_spans() runs on the write path and the read path, so an invalid tree is never written and a corrupt spans.jsonl fails at load. 70 tests.
  10. Redaction & safety hygiene complete
    The promise docs/SAFETY.md makes: no credential-like or PII-like string is ever written to a trace, a span, or a report. traces/redaction.py is the single definition of "credential-like" in this repository — the trace writer, the span writer, the report gate and llmreg validate-fixtures all read one table, because the copy that misses a pattern is the one that runs. Four decisions carry it. Refuse on evidence, mask on suspicion: the twelve rules split into a certain tier (provider key prefixes sk-…/AKIA…/gh[pousr]_…/AIza…/xox…, a JWT, a private-key header, Bearer, Authorization) that can block an artifact, and a heuristic tier (a credential-named assignment, an email, a generic high-entropy token) that masks and never blocks — a false-positive refusal is a denial of service on your own report, while a false-positive mask costs one mangled string that redaction_status then records. The same asymmetry keeps the repository scan quiet: it applies the certain tier only, because a hygiene check that flags every SHA-256 digest in docs/ and every author email in pyproject.toml is a hygiene check that gets skipped. Identity fields are scanned, never rewritten: run_id, case_id, model_id, a tool_calls[].name, a retrieval_sources[].source_id, an errors[].kind are all join keys — the engine pairs by case id and the tool evaluator diffs by tool name — so masking one would destroy the artifact's meaning while claiming to protect it. A certain-tier match there yields redaction_status="flagged" and the executor refuses the run, naming the field and the pattern but never the value. That is why flagged can never appear in a file this project wrote; it exists for traces imported from elsewhere (Milestone 10). The status is derived, and only moves one way: clean < redacted < flagged, and redact_record() takes the maximum of what this pass found and what the record already carried — a claim of clean over a live secret is overruled because the scan is the authority, while a claim of redacted survives a second pass that finds only placeholders left. The monotone rule is what makes redact(redact(r)) equal redact(r) in bytes and status. It runs inside execute_suite, not write_run: run_meta.json publishes records_sha256 over run.jsonl, so a redactor at write time would hash text that no longer exists — and running it before accounting means output_tokens_estimate describes the text actually persisted rather than quietly encoding the length of the secret. Spans got the answer Milestone 8's review note asked for: they are a gate target, not a mask target, because every string in a span is a symbol the pipeline indexes by. The load-bearing result is that all 52 committed fixture records pass through redaction byte-identical and report clean — redaction rewrites final_output before any evaluator reads it, so a false-positive mask would silently change a score, and a test now fails rather than letting a future rule cause mysterious evaluator drift. llmreg scan-secrets and scripts/08_check_repo_hygiene.py scan the tree (0 findings), honoring a redaction:allow marker for the lines that must name a credential shape in order to test the scanner. 73 tests.
  11. Integration contracts complete
    The boundary. A trace produced outside this repository enters through an importer that maps it onto RunRecord; the evaluators, comparison engine, span projection and report generator then run over it unchanged. Six importers ship — llmreg (the identity map), code_agent_runtime, bioagentbench, bioscientist_os, agent_control_bench, claude_api — and none of those repositories is required, present, or read: their shapes are declared here and pinned against committed synthetic examples under data/external/. Four decisions carry it. An importer may not drop a field in silence — every key is mapped, listed in ignored_fields, or unknown, and an unknown key refuses in strict mode rather than disappearing; you want to know a field appeared before you score against it. It may not invent a measurement. A claude_api response carries no duration, and importing it as 0.0 would not be missing data — it would be a number, and the comparison engine believes numbers: against a timed baseline it reads as an improvement (relative(0, 300) == -1.0), and as the baseline it makes every candidate an unbounded latency_regression (relative(300, 0) == inf). So a record with no recorded duration is refused rather than scored. It may not guess an attribution — app vs infra is this repo's distinction and no external system emits it, so each importer publishes an error_origins table and an unmapped kind resolves to app and warns: infra withholds flags, so guessing it would silently suppress a real regression, and a false flag gets investigated where a silent suppression does not. It may not import a secret — this is the edge Milestone 9 named. redaction_status="flagged" was unreachable on a trace this project wrote; it becomes reachable here, so content is masked and a credential-like string in a join key refuses the import, naming the field and the pattern but never the value. The envelope (TraceBundle, contract 1.0) carries a record_schema fingerprint derived from the dataclass rather than declared, so changing RunRecord invalidates every exported bundle whether or not anybody remembered to bump a constant; exported_at is a recorded input, never the clock, so two exports of one run are byte-identical and payload_sha256 stays useful as a change detector. Spans are deliberately not in the payload — they are a pure projection the receiver can recompute and cannot verify, so an imported record gets the whole observability layer for free. And an import is executed, not written: ImportedTraceAdapter is handed to the ordinary execute_suite(), which buys identity re-stamping, redaction-before-accounting, token/cost estimation and records_sha256 without a second artifact writer to drift against. import_meta.json lands next to run.jsonl and records what the mapping could not carry — warnings, ignored fields, unmapped fields, absent fields — because a comparison that reads clean over a trace half of which never arrived is exactly the quiet lie this project exists to prevent. End to end, two imported code-agent sessions over the four-case external suite yield exactly the two injected defects (tool_call_regression critical on tu_wrong_tool, error_rate_regression warn on at_more_retries) and 0 false positives on the two controls, with no evaluator, comparison rule or report template touched. 101 tests.
  12. Optional API adapter stub & cost guard complete
    The one code path in this project that could cost money, and the seven gates in front of it (Cost guard). The guards are the deliverable; the network call is not — the package ships no network client, anthropic is not a dependency, and tests/test_api_stub.py proves it by parsing the package's own source with ast, because a runtime sys.modules check only sees the imports that happened to run; the scanner is itself unit-tested against a top-level import, a try:-wrapped import and an if:-wrapped import, so it cannot silently match nothing and make every assertion below it vacuous. Every call climbs a fixed ladder — opt-in → cache → estimate → dry-run → verified pricing → ceiling → transport — and the order carries the design. Opt-in is first, so a disabled adapter does not even stat a cache file. The cache is consulted before the budget, because a hit spends nothing and must not consume budget — otherwise a completed suite could never be re-run under the ceiling it already paid — and before the dry-run branch, so a dry run over a warm cache returns the real answers, free; a hit still reports what the call cost when it was made, because that is the case's cost and the comparison engine is right to see it, while the ledger stays untouched because this run spent nothing. Dry-run is the default even once opted in: "I want to use the API adapter" and "I want to spend money right now" are different intentions and one flag cannot tell them apart. The ceiling is checked before the transport is looked for — budget and pricing are policy, decided without reference to whether a client happens to be installed — so an over-budget suite makes zero calls, not n − 1; it defaults to 0.0, because the failure mode "I meant to set it and forgot" must cost nothing; and it refuses rather than truncating, since silently shrinking max_tokens to fit a budget changes the experiment, and a harness that quietly changes the experiment to stay in budget is worse than one that stops. A pre-call estimate bounds cost rather than predicting it: input tokens are knowable, output tokens are not, so output is priced at max_output_tokens — a guard that priced the average output is a guard that lets the tail through — and output_tokens_bounded records which of the two any number is, so a report can never present an upper bound as a measurement; the ledger then settles from the provider's reported usage, so the guard reasons about what could be spent and the ledger tracks what was. A transport that reports zero tokens or zero latency is refused, which is Milestone 10's rule restated: an absent measurement recorded as 0.0 is not missing, it is a number, and the comparison engine believes numbers. The estimator moved into one home, pricing.py, shared by the executor's artifacts, the cost evaluator's metric, the comparison engine's delta and the guard's ledger — COST_DECIMALS had been declared three times and kept in sync by comment, which is survivable until an estimate is what stands between a run and a bill; the refactor touched scored paths and changed no artifact (smoke baseline sha256(run.jsonl) still ee23bfde…). Beyond the spec: a PriceList carries verified/priced_at provenance and the spend path refuses an unverified list, because a ceiling enforced against prices nobody checked is theater, while estimating with them is perfectly sound (both sides of a delta use the same prices); a verified: true list with no priced_at is rejected outright, since a "verified" claim with no date cannot go stale, which is the problem. llmreg estimate-cost prices a suite it never runs and exits 1 over the ceiling, so it can gate a job before the job can spend. And "no test uses the network" became a mechanism rather than a convention: an autouse conftest.py fixture disables outbound TCP for all 956 tests, with one test asserting the fixture is armed. Adversarially checked: removing the ceiling check fails 5 tests, removing the cache lookup fails 6. 97 tests.
  13. Final portfolio report complete
    The README, docs/RESULTS.md and this website brought to the standard the code already meets — and then held there. The deliverable is not the prose; it is tests/test_docs.py, because a document is the one artifact in this repository where a number can be wrong and nothing fails. It recomputes the detection counts, every flag and cluster id, the smoke verdict, the baseline digest and the suite's own test total from the fixtures, and fails when a document quotes a stale one. Two decisions carry it. Structured claims are parsed, not matched: the ComparisonRecord the README prints for tu_wrong_tool is extracted from its fenced JSON block and compared field by field — explanation string included — against the record the engine writes during the test, so a changed threshold or a reworded rule breaks the README rather than being silently contradicted by it. Prose is compared with the typography removed (tags, emphasis, table pipes, line wrapping), because matching raw bytes fails on a reflow and passes on a lie, which is exactly backwards; the first version of that helper had a greedy <[^>]+> that ate every word between +20% < 25% and the next > in the file, and the tests it silently disabled are what caught it. The README now leads with the case that carries the thesis: tu_wrong_tool's final_output is byte-identical across baseline and candidate while a tool call quietly disappeared — a string diff sees nothing, and the engine raises tool_call_regression, critical; its mirror sj_control_reorder changes the string and regresses nothing. docs/RESULTS.md gained a per-dimension table covering all 18 defects (including the row where at_more_retries clears the 50 ms absolute floor, misses the 25% relative one, and correctly raises no latency flag), the complete 16-cluster listing — it had claimed 16 and shown 8 — a table of all 8 negative controls, and the imported-trace result; the forward-looking section that still described Milestone 10 as future work is gone. Four stale test counts across five files, one under-counted cluster table, and one report-test count off by one were all found by the new tests rather than by reading them. 64 tests.
  14. Final cleanup complete
    Section 11 of docs/PLAN.md lists ten conditions this repository must meet to be called complete. Each was already true; each was checked by a different command, in a different output format, by a human reading the result. The deliverable is scripts/10_run_all_gates.py, which runs all ten in dependency order and exits non-zero if any required one fails — and tests/test_gates.py, which parses §11 and asserts the ten required gates reproduce its ten bullets verbatim, in order, so a gate cannot drift away from the promise it keeps. Writing it was worth more than restating the checklist, because three gates as originally drafted would have passed while proving nothing. smoke_offline now enforces offline rather than asserting it: the two run scripts execute in a child interpreter whose socket.connect, connect_ex and create_connection raise, so a run that reached for the network fails even on a connected host. redaction proves its own scanner is live: an inert scanner reports zero findings on every tree, including one with a key in it, so the gate plants a synthetic credential in a scratch file and requires the scanner to find that before it accepts an empty finding list for the repository. report compares bytes, not shapes — the rendered Markdown must equal the committed example exactly, which is only possible because the report carries no timestamp. Two design choices keep the output honest: the pipeline gates write into a scratch directory outside the tree, so clean_tree inspects the repository rather than the leavings of the gate before it; and --json carries no clock and no scratch path, so two runs on one commit are byte-identical and a gate report diffs like any other artifact here. The docs gate was rewritten mid-milestone after its first draft checked whether REPRODUCIBILITY.md contains the word "reproduction" — it does not, and it should not have to; a gate cannot read English, so it checks that each document exists, is not a stub, and is linked from the README. The tests gate raises rather than forking the suite into itself when selected from inside pytest. One real lint finding (E501 in the environment preflight) was swept up. And the runner caught a bug in itself on its first full run: this project's addopts is already -q, so the tests gate's own -q made it -qq, at which pytest prints no N passed summary at all — a passing suite read as an unparseable one. -o addopts= makes the gate run exactly the command §11 names whatever the config says, -p no:cacheprovider stops it writing .pytest_cache/ into a tree whose cleanliness it is about to assert, and two tests pin both directions of the failure. 43 tests; 956 total, 10/10 required gates green, working tree clean, nothing pushed.
