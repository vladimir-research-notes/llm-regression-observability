llm-regression-observability
A CPU-first framework for detecting, explaining, and reporting regressions in LLM applications and agentic systems.

Milestones

The system is built in fourteen milestones (0–13), one commit each. Each is implemented by a single claude -p run driven by scripts/run_all_milestones_with_claude.sh, which stops on agent failure, no new commit, a dirty tree, or a failing test. Full specs live in docs/milestones/.

status: Milestones 0–8 complete (scaffold, CLI, tests; typed data contracts; fixture suites; deterministic adapters; run-suite executor; evaluators; comparison engine; reports; observability); Milestone 9 next

  1. Scaffold & project contract complete
    Package skeleton, pyproject.toml (dependency-free core), llmreg CLI (version, check-env) with a python3 -m entry, a conftest.py path shim, and 14 CPU-only tests (test_smoke.py, test_scaffold_layout.py). The layout test enforces the empty runtime-dependency list.
  2. Core schemas & trace model complete
    Typed contracts — EvalCase, EvalSuite, RunRecord (alias ModelTrace), ToolCallTrace, RetrievalTrace, RetrievalDoc, ErrorRecord, MetricResult, ComparisonRecord, RegressionFlag, ReportSummary, FailureCluster — as stdlib dataclasses in schemas.py. Annotation-driven validation (missing/unknown field, wrong type, enum vocab, int→float coercion) raising SchemaError; byte-stable to_json() with sorted keys; 54 round-trip/rejection/stability tests.
  3. Fixture suites complete
    Six synthetic suites (structured JSON, tool use, retrieval/evidence, refusal boundary, latency/cost, agent trace) — 26 cases: 18 injected defects + 8 negative controls. Cases (EvalCase) and per-case ground truth (CaseExpectation) live under evals/fixtures/; recorded baseline/candidate RunRecords under data/fixtures/. A stdlib-only restricted-YAML reader parses evals/suites/smoke.yaml. The validator (llmreg validate-fixtures / scripts/01_validate_fixtures.py) checks schemas, referential integrity, that each injected defect actually differs from its baseline, manifest resolution, and a credential-like-string safety scan. 25 fixture tests.
  4. Adapters complete
    Four deterministic adapters in adapters/. AdapterContext (run identity: app_version, model/prompt/tool versions, recorded timestamp) is kept separate from AdapterResponse (behavior: output, tool calls, retrieval, errors, tokens/latency/cost); build_run_record() joins them, so no scored path ever reads the clock. RecordedModelAdapter replays all 52 committed fixture records byte for byte. ScriptedRegressionAdapter applies one of 15 pure injectors (invalid JSON, dropped/wrong/extra tool, arg drift, order swap, unsupported claim, dropped citation, refusal flip, added latency/cost, injected error) to a clean baseline; its plan is derived from the Milestone 2 CaseExpectation ground truth, so non-controls get a defect of their annotated category, infra-attributed cases get an infra-origin error, and true controls are left untouched. ApiAdapterStub raises when disabled (the default) and still raises when enabled — no default path reaches a paid API. 46 adapter tests.
  5. Run-suite executor complete
    llmreg run-suite (in executor.py) resolves a suite manifest into an ordered EvalSuite, drives an adapter over every case, and writes results/runs/<run_id>/run.jsonl plus a run_meta.json sidecar (identity, totals, cost model, SHA-256 of the records). Three decisions the spec left open are settled here. The executor owns run identity: it re-stamps run_id and app_version onto every replayed record — so (run_id, case_id) keys the artifact — while model_id, prompt/tool versions, and timestamp stay as the adapter reported them unless explicitly overridden. Latency is recorded, never measured: timing the adapter would put an ambient value into a scored field. Tokens and cost are derived only where the adapter left zeros, and run_meta.json counts how many records took that path, so no artifact hides which numbers were invented. Byte-stable persistence (sorted keys, compact JSONL, explicit UTF-8 and \n) lives in one place, traces/storage.py. 51 executor tests, including an AST scan that fails if the new modules import time, datetime, random, or anything network-shaped.
  6. Evaluators complete
    Ten deterministic scorer modules in evaluators/, each a pure function of (EvalCase, RunRecord): structural task_success (opt-in exact_match), JSON parse/schema validity and field diff (against a stdlib JSON Schema subset — no jsonschema dependency), tool-call drift (allowed-tool ratio, order-sensitive sequence similarity, missing/extra tools, argument distance), evidence grounding (citation presence/correctness, coverage, unsupported claims), refusal shift and risk-label drift, recorded latency with type-7 p50/p95, cost, error classification, and trace completeness. Three decisions carry the design. A metric that cannot be computed is not emitted — an absent metric means not applicable, never zero, so field_diff_count stays silent when the output did not parse and one defect never counts twice. Direction lives in a table (METRIC_DIRECTION), and NEVER_FLAG_METRICS guarantees the two placeholders (semantic_similarity_stub, explanation quality) and the infra counters can never raise a regression. Trace completeness is a harness signal, not an application score: a broken JSON output is a regression with a complete trace, while a record with no latency is an incomplete trace — which is what lets Milestone 6 exclude harness failures instead of scoring their zeros. 155 tests assert exact expected scores for all 26 fixture cases × both sides; the eighteen injected defects each move exactly the metric they target, and an AST scan fails if any of the thirteen modules imports time, datetime, random, or anything network-shaped.
  7. Baseline vs candidate comparison complete
    The heart of the system. llmreg compare loads two runs, pairs them by case_id (a case present on one side only is reported unpaired, never scored as a success), diffs the behavioral fields, and applies eight threshold rules read from the suite manifest. Detection on ground truth: 18 of 18 injected defects, with the category and severity each fixture's expected.json annotates; 0 false positives on the 8 negative controls. Three decisions carry the design. One defect, one signal — task_success is the union of a case's declared properties, most of which another dimension already owns, so a task-success drop is attributed (PROPERTY_CATEGORY) and final_answer_regression fires only on an answer-level property; without it all 18 defects would report twice. A new unsupported claim is critical; a claim that lost its support is a warning — both raise unsupported_claim_count 0→1, so the rule compares claim texts to tell an invented fact from degraded grounding. Harness noise is withheld, not dropped — when every error on a candidate record is origin=infra, its flags are suppressed and written to comparison_meta.json, which is research question 9 and a documented masking risk. Failures cluster by (category, signature) — disallowed_tool:shell_exec, not "a tool was wrong" — with no fitted distance metric, because a fitted grouping could not be reproduced from the artifact. Latency and cost each need a relative and an absolute floor. 96 tests; two comparisons of the same runs are byte-identical.
  8. Reports complete
    The product's surface. llmreg report renders a comparison as Markdown and as one self-contained HTML file: verdict and provenance, per-category changes, worst regressions, a worked example each for structured output / tool-call diff / evidence grounding, structured-output validity, latency and cost tables, failure clusters, thresholds applied, and a limitations note. Four decisions carry it. The report reads the artifacts and nothing else — comparison.jsonl, summary.json, comparison_meta.json — so it is reproducible from a directory a colleague hands you and cannot quietly enrich itself from a source the reader lacks; the visible cost is that the structured-output table shows a delta (-1) rather than the two absolute validity values, which no artifact records. Selection happens once, in a shared ReportModel: the renderers lay out tables, they do not choose rows, so Markdown and HTML can never disagree about which regression is worst. Redaction is a fail-closed gate, not yet a mask — the fully rendered document is scanned for credential-like strings immediately before the bytes hit the disk, and one that survived the redactor seam is refused, not written; the error names the pattern and the line but never echoes the value, and --dry-run runs the same gate so it cannot pass where a write would refuse. Milestone 9's masking redactor plugs into that seam and the gate stays put. The silences get their own section — "what the engine declined to say" prints unpaired cases, infra-attributed cases and withheld flags, because a clean headline over a comparison that could only look at half its cases is the failure mode this project exists to avoid. Sub-threshold latency and cost moves are rows too, so a working tolerance is visible rather than implied. No clock, no RNG, and no generation timestamp: two reports of one comparison are byte-identical, and a committed sample in docs/examples/ is regenerated by a test so it cannot go stale. 66 tests.
  9. Observability layer complete
    What makes the application-vs-harness distinction operational. llmreg aggregate projects each run into a nested, OpenTelemetry-shaped span tree (request → model_call / tool_call / retrieval / evaluator, no OpenTelemetry dependency) and reduces its per-case MetricResults to suite numbers, writing results/runs/<run_id>/spans.jsonl and results/processed/<run_id>/aggregate.json. Four decisions carry it. Spans are derived, not emitted — nothing here instruments a live call, because there is no live call; the projection is a pure function of (case, record, metrics), so the tree is rebuildable and byte-identical, and span ids are content-addressed (sha256(run_id | case_id | path)) rather than random. That is also why the stage holding both the trace and the scores owns the file: an evaluator span needs a metric, and the executor has never scored anything. Only one duration was ever recorded. The trace carries latency_ms and nothing else, so the request span's interval is recorded, its application children get a contiguous partition of that interval in trace order (derived — which asserts ordering, not duration: a child's width is latency_ms / step_count and means nothing alone), and evaluator spans are zero-width at the request's end (none) because scoring happens afterwards, in the harness. Inventing per-step durations was the easy lie available here; labelling every span with its timing source was done instead. Spans carry symbols, never free text — a tool name, a source id, a metric name, an error kind, argument keys, counts, statuses; never a prompt, an output, a tool argument value, a snippet, or an error message, because Milestone 9's redactor has not run and until it has, no telemetry artifact may copy a string. A test scans every attribute of all 52 committed fixture records against the free text of the record it came from. The suite summary keeps three maps, not one: application_metrics, harness_metrics (trace_completeness, infra_error_rate, incomplete_trace_rate) and placeholder_metrics. A flat map lets a broken exporter and a broken model look alike at a glance, so the separation is structural rather than a naming convention. On the smoke candidate, at_more_retries moves error_rate to 0.125 and at_infra_noise moves infra_error_rate to 0.125 — two errored cases, two different maps. Reducers are named (ratio counts cases, mean counts events), direction is inherited from METRIC_DIRECTION rather than restated, and metric_coverage says how many cases answered each number. validate_spans() runs on the write path and the read path, so an invalid tree is never written and a corrupt spans.jsonl fails at load. 70 tests.
  10. Redaction & safety hygiene
    Mask fake API keys, secrets, bearer tokens, emails, credential-like strings — before any report is generated. Proven by tests.

  12. Optional API adapter stub & cost guard
    Disabled by default: dry-run mode, token/cost estimator, hard max-cost guard, response cache, explicit opt-in. No real API in any test.
  13. Final portfolio report
    README, docs/RESULTS.md, and website brought to portfolio quality with real, reproducible smoke-run numbers.
  14. Final cleanup
    Run every quality gate end to end; verify no secrets/large logs/caches; leave a clean working tree. Nothing pushed.

How a milestone runs

./scripts/run_all_milestones_with_claude.sh        # milestones 0..13
./scripts/run_all_milestones_with_claude.sh 4 6    # a subrange

Each run reads CLAUDE.md, the plan, and the milestone spec; implements exactly one milestone; updates docs and this website; writes a human-review placeholder; and commits locally.
