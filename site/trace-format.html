Trace format

All artifacts are JSON / JSONL, defined as typed schemas in schemas.py. Line-delimited JSON is used for record streams (append- and diff-friendly); plain JSON for single-object summaries. The full contract is docs/TRACE_FORMAT.md.

status: contract implemented in schemas.py (M1), persisted by traces/storage.py (M4), produced end to end through ComparisonRecord / ReportSummary / ComparisonMeta (M6), and extended with Span / RunAggregate (M8) — round-trip and byte-stability under test

EvalCase

case_id, version, prompt, input_payload, expected_properties,
json_schema?, allowed_tools?, retrieval_docs?, tags, risk_category

Expected behavior is expressed as properties (contains, equals, matches, numeric range, schema-valid), not a raw expected string.

RunRecord

run_id, case_id, app_version, model_id, prompt_version, tool_version,
timestamp, input_tokens_estimate, output_tokens_estimate, latency_ms,
cost_estimate_usd, final_output, parsed_output, tool_calls[],
retrieval_sources[], errors[], redaction_status

One record per (case, run), written to results/runs/<run_id>/run.jsonl. ToolCallTrace carries name, arguments, order index, status, error; RetrievalTrace carries source id, snippet, claim, and whether the snippet supports the claim; ErrorRecord carries kind, message, and origin (app | infra) — the field that drives harness-noise filtering.

RunMeta

run_id, suite_id, suite_path, adapter, app_version,
model_id, prompt_version, tool_version, timestamp,
case_count, input_tokens_total, output_tokens_total, cost_total_usd,
latency_ms_total, tool_call_count, retrieval_source_count,
error_count, app_error_count, infra_error_count,
tokens_estimated_cases, cost_estimated_cases,
identity_overrides[], cost_model, records_sha256, llmreg_version

The sidecar written next to each run.jsonl, at results/runs/<run_id>/run_meta.json (Milestone 4). Its totals are derived from the records, so the file is a self-check: recompute them from run.jsonl and they must agree, and records_sha256 must equal the SHA-256 of that file's bytes. A provenance field that is not constant across the run's records reads "(mixed)".

Identity vs. provenance

run_id and app_version are identity: the executor forces them onto every record in a run, so (run_id, case_id) is the artifact key. model_id, prompt_version, tool_version and timestamp are provenance: preserved exactly as the adapter reported them — the recorded adapter replays committed fixture values — unless the caller overrides them, in which case the field name appears in identity_overrides.

The two token fields and cost_estimate_usd are recorded inputs when the adapter supplies them and derived by the executor otherwise; tokens_estimated_cases and cost_estimated_cases say how many records took the derived path, so no artifact hides which numbers were invented. latency_ms is always a recorded input — the executor never times the adapter.

ComparisonRecord

case_id, baseline_run_id, candidate_run_id, changed_fields[],
score_delta, latency_delta, cost_delta, json_validity_delta,
tool_call_delta, refusal_delta, evidence_delta,
regression_flags[], human_readable_summary

One record per paired case, in the baseline's run order. changed_fields lists only the fields describing what the application did: run identity (run_id, app_version) and provenance (model_id, timestamp, …) differ between every baseline and candidate, and reporting them would bury the one field that matters.

Each delta is candidate − baseline on that dimension's headline metric, and 0.0 when the case never declared the dimension. A zero delta is not a claim that nothing changed — regression_flags is the claim. Tool-argument drift and a refusal-decision flip move no delta at all; they are pairwise, and they surface as flags.

A RegressionFlag carries category, severity, the triggering metric, the observed value, the threshold, an explanation, and an attribution (app vs infra). There is at most one flag per (case, category): when several conditions fire, they collapse into the strongest, which names the rest in its explanation. Values are always finite — a guard rejects inf/nan, which json.dumps would render as the non-standard Infinity.

ReportSummary

comparison_id, suite_id, baseline_version, candidate_version,
case_count, regressed_case_count, flags_by_category,
latency_p50_delta, latency_p95_delta, cost_total_delta, clusters[]

FailureCluster: cluster_id, label, category, case_ids[]

Percentiles and totals are computed over the paired cases only. cluster_id is derived from content (<category>__<signature>), not from an ordinal, so adding a case to a run never renumbers the clusters an earlier report referred to.

ComparisonMeta

comparison_id, suite_id, suite_path,
baseline_run_id, candidate_run_id, baseline_version, candidate_version,
baseline_adapter, candidate_adapter, paired_case_count,
unpaired_baseline_case_ids[], unpaired_candidate_case_ids[],
infra_attributed_case_ids[], infra_suppressed_categories{},
cost_comparable, comparability_notes[], thresholds{},
flag_count, critical_count, warn_count,
baseline_latency_p50/p95, candidate_latency_p50/p95,
baseline_cost_total_usd, candidate_cost_total_usd,
records_sha256, llmreg_version

summary.json answers what regressed; this sidecar answers what the engine declined to say, and why. An unpaired case and an infra-suppressed flag are both invisible in the summary's counts, and both are exactly the kind of silence that makes an evaluation harness lie.

Conventions

  • Sorted keys, fixed field order → byte-stable, diff-friendly output. Implemented once, in traces/storage.py: sorted keys, compact JSONL separators, ensure_ascii=False, explicit UTF-8, explicit \n (trailing included).
  • No ambient values — timestamps and seeds are inputs.
  • Redaction before persistence — text is masked before any write to results/ or a report.

Current implementation status

Milestone 1 complete. Every type above is a stdlib dataclass in schemas.py with a shared base that gives each model to_dict(), to_json() (sorted keys), from_dict(), and from_json(). Validation is driven by the field annotations: it coerces int → float for float fields (so numeric artifacts never drift), and raises a SchemaError — naming the offending path — on a missing required field, an unknown field, a wrong type, or an out-of-vocabulary enum value (risk_category, tool status, error origin, redaction_status, flag severity/attribution). ModelTrace is an alias of RunRecord. 54 tests cover round-trip, rejection, and byte-stable output.

Milestone 4 complete. traces/storage.py is the single place these types reach disk, and the run executor emits the first real artifacts: run.jsonl and run_meta.json under results/runs/<run_id>/. Readers validate every line against its schema and report path:lineno on malformed input, so a corrupt artifact fails at load rather than halfway down the pipeline.

Milestone 6 complete. llmreg compare produces the comparison side of the contract: comparison.jsonl, summary.json and comparison_meta.json under results/comparisons/<comparison_id>/. The writer re-hashes the records file against ComparisonMeta.records_sha256 after writing, and two comparisons of the same two runs produce byte-identical files. No Milestone 1 schema changed to accommodate the engine.

redaction_status (Milestone 9)

Derived by traces/redaction.py, never believed from the adapter that produced the record. The values form a lattice — clean < redacted < flagged — and redaction takes the maximum of what it found and what the record already claimed, so the status can only escalate and redacting twice changes nothing.

  • clean — no rule fired.
  • redacted — a rule fired in a content field (final_output, parsed_output, tool-call arguments, an error, a snippet, a claim, an error message) and was masked with [REDACTED:<rule>].
  • flagged — a credential-like string sits in an identity field: run_id, case_id, model_id, a tool_calls[].name, a retrieval_sources[].source_id, an errors[].kind. The redactor will not rewrite these, because the pipeline joins on them. A flagged run is refused, so the value never appears in a file this project wrote — it exists for traces imported from elsewhere.

Redaction runs inside execute_suite, before tokens are accounted and before run.jsonl is hashed, so records_sha256 digests the redacted bytes. See Safety.

Span (Milestone 8)

trace_id, span_id, parent_id?, name, case_id, run_id,
start_ms, end_ms, status, attributes

Written to results/runs/<run_id>/spans.jsonl. One case is one trace; name is one of request, model_call, tool_call, retrieval, evaluator. Ids are content-addressed — span_id = sha256(run_id | case_id | path)[:16], where path is the span's position in the tree — so an id is a function of where the span sits, never of when it was generated.

attributes["timing"] says where the interval came from. The trace records exactly one duration, latency_ms: the request span is recorded, its application children get a contiguous partition of that interval in trace order (derived — ordering, not duration), and evaluator spans are zero-width at the request's end (none), because scoring happens afterwards in the harness.

status is about the operation, not the score: an evaluator span reporting passed=false is ok. Errors attach to the request span with their origin and kinds, because ErrorRecord names no step. Attributes hold symbols, never free text — a tool name, a source id, a metric name, an error kind, argument keys, counts, booleans; never a prompt, an output, a tool argument value, a snippet, or an error message.

RunAggregate (Milestone 8)

run_id, suite_id, app_version, adapter, case_count, metric_count,
application_metrics, harness_metrics, placeholder_metrics, metric_coverage,
spans, incomplete_trace_case_ids, infra_attributed_case_ids,
metrics_sha256, spans_sha256, llmreg_version

Written to results/processed/<run_id>/aggregate.json. Suite metrics live in three maps so a broken exporter and a broken model cannot look alike at a glance.
