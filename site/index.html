Detecting regressions in stochastic, tool-using LLM systems

Model, prompt, tool, and deployment versions go in; evaluation traces, observability metrics, and regression reports come out. The system answers one hard question: when outputs are stochastic, multi-step, tool-using, and not reducible to exact string matching, did a change make behavior worse — and how?

status: Milestone 0 complete — package skeleton, llmreg CLI, first tests passing

This is a reliability/evaluation framework, not a medical, legal, or security authority. All fixtures are synthetic. See Limitations and Safety.

Why exact match is not enough

Two correct answers can differ token for token. A valid JSON object can be phrased many ways. An agent can reach the right final answer through a worse process — more retries, more failed tool calls, a disallowed tool, twice the latency, twice the cost. A test that flags every string change is uselessly noisy; a test that watches only the final string is uselessly blind. So a regression is reframed as "a measurable behavioral property got worse," and measured across independent dimensions.

How it works

cases + adapter ──▶ RunRecords (traces) ──▶ ComparisonRecords ──▶ Report
   (baseline)                                    (deltas +
   (candidate)                                    regression flags)

A baseline run (known-good version) and a candidate run (the change) are executed over the same synthetic suite, compared case by case, scored on every dimension, flagged against configurable thresholds, clustered, and turned into a Markdown/HTML report. Deterministic mock / recorded / scripted-regression adapters make the whole pipeline runnable with no model call and no network.

Design constraints

  • CPU-only, target AWS m5.2xlarge. No GPU.
  • Offline and free by default — no test needs the internet or a paid API.
  • Dependency-free core — Python 3.12 standard library only; pydantic/pandas optional.
  • Deterministic — same inputs produce byte-identical outputs.
  • Any optional paid-API adapter is disabled by default and gated by dry-run, cost estimator, hard max-cost guard, response cache, and explicit opt-in.

Open questions / limitations

All fixtures are synthetic; results do not generalize to production traffic. Costs are transparent estimates, not bills. Some scorers (explanation quality, semantic similarity) are explicit placeholders. See Limitations.
