Metrics

Every metric is computed by a deterministic evaluator: a pure function of (EvalCase, RunRecord), with no clock, no RNG, no network, and no learned model. Ratios are normalized to [0, 1]; everything else is reported in native units (ms, USD, counts). Full definitions in docs/METRICS.md.

Two rules that govern the whole package

A metric that cannot be computed is not emitted. Scoring a case that declares no json_schema as json_schema_validity == 0 would invent a failure. Each evaluator states its precondition and stays silent otherwise; the comparison engine reads an absent metric as not applicable, never as zero. The sharpest case: field_diff_count is silent when the output did not parse, because a field diff against an object that does not exist is the parse failure — counting both would make one defect look like two.

Direction is metadata, not convention. METRIC_DIRECTION records whether each metric is better high, better low, or neither, so the comparison engine flags "worse" without hard-coding a sign. NEVER_FLAG_METRICS names what may never raise a regression at all: the two placeholders, and the infra counters.

Honest by design

  • Cost is estimated from a transparent char-based token estimator (tokens ≈ chars / 4) times a synthetic price table — a figure for relative comparison, never a bill. The evaluator reads the recorded value rather than re-pricing, so a cost regression can never be an artifact of two different price lists.
  • Structural, not string-equal. Task success checks properties from a closed vocabulary; exact match is opt-in and no fixture uses it. A property a single record cannot answer is either pairwise (final_output_stable) or advisory — and either way it is named in the metric's detail, never silently dropped.
  • Placeholders are labeled and defanged. Explanation quality always emits 0.0; semantic_similarity_stub is lexical token overlap, which rates a paraphrase low and a fluent contradiction high. Both carry detail["placeholder"] and sit in NEVER_FLAG_METRICS.
  • Evidence support is recorded, not judged. Nothing here reads a snippet and decides whether it entails a claim.
  • Infra errors are separated and never raise a regression flag. A record is attributed to infrastructure only if every error on it is infra-origin; one app error makes the whole record the application's fault.
  • The JSON Schema validator is a documented subset. The core is dependency-free, so jsonschema is not an option. Any keyword outside SUPPORTED_KEYWORDS is surfaced in detail["unsupported_keywords"] — ignoring one would let an invalid document score as valid.
  • The percentile method is pinned. p50/p95 use linear interpolation between closest ranks ("type 7"). A threshold is only meaningful if p95 means one thing.

Trace completeness is a harness signal

Every other metric assumes the trace says what happened; trace_completeness asks whether it does. A run whose latency was never recorded scores as the fastest in the suite. So a drop here means the harness or the exporter is broken — not that the application regressed. The asymmetry matters: a candidate whose JSON genuinely broke has parsed_output = null and scores trace_completeness = 1.0 (a correct trace of a real failure), while the executor's --continue-on-error record scores 0.777778. All 52 committed fixture records score 1.0.

Milestone 8 makes that separation structural rather than advisory: trace_completeness and infra_error_rate land in aggregate.json's harness_metrics, never in application_metrics. On the smoke candidate, two of eight cases errored — at_more_retries moves error_rate to 0.125, at_infra_noise moves infra_error_rate to 0.125, and neither number contains the other's case. Zeroing a record's recorded latency drives incomplete_trace_rate up and leaves success_rate at 1.0: a broken harness is not a regression.

Aggregation (Milestone 8)

Suite-level numbers are means / sums / percentiles over per-case MetricResults, computed with the standard library only. pandas is an optional convenience for ad-hoc summaries, never required. Values are rounded to six decimals (cost_estimate_usd to eight), so a score serializes to identical bytes on any platform and a threshold comparison cannot hinge on the last bit of a float.

A reducer is named, not assumed. mean, sum, p50, p95, ratio. ratio is the fraction of cases with a non-zero value, which is what makes app_error_count → error_rate mean "how many cases errored" rather than "how many errors, averaged": two errors on one case out of eight is a rate of 0.125 and a mean of 0.25. A rate is about cases, not events.

Direction is inherited, never restated. Every reducer is monotone, so a suite metric is worse in the same direction its per-case metric is worse. MetricSpec.direction reads METRIC_DIRECTION; a second table that could silently disagree with the first never exists.

The summary keeps three maps, not one. application_metrics are scores for the system under test; harness_metrics (trace_completeness, infra_error_rate, infra_error_total, incomplete_trace_rate) describe whether the observation can be trusted; placeholder_metrics are computed and claimed for nothing. A flat map would let a broken exporter and a broken model look alike at a glance. metric_coverage records how many cases contributed to each number, because evidence_coverage_mean = 1.0 over 1 of 8 cases is a fact about one case.

tool_arg_diff and risk_label_delta are pairwise — they compare two records, so a single run never emits them and no suite metric reduces them. The comparison engine owns that dimension. A test asserts that every per-case metric the fixtures do emit has a suite metric, so a new scorer cannot be added and then silently vanish from the suite.

Open questions / limitations

Deterministic evidence scoring has a known ceiling versus a learned entailment model: supported is a recorded field of the trace, not a judgment. citation_presence is 1.0 on every committed fixture, because the trace model can only express an uncited claim as an empty source_id; it exists for imported traces. One fixture property (expected_source_for_color) is prose and lands in the advisory list rather than being scored — a test pins that set so it cannot grow silently. See Limitations and Roadmap.
