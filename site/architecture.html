llm-regression-observability
A CPU-first framework for detecting, explaining, and reporting regressions in LLM applications and agentic systems.

Architecture

Data flows one direction: cases plus an adapter produce run records; two runs are compared into comparison records; comparison records render into a report. Every stage writes inspectable JSON/JSONL artifacts so it can be re-run or examined on its own.

status: contract defined; stages implemented across Milestones 1–8

Why file-based stages

Each stage persists its output before the next begins. That makes the system debuggable (inspect the JSONL), reproducible (re-run any stage on committed artifacts), and portable (a trace imported from another runtime enters at the executor boundary). Observability spans — request, model call, tool call, retrieval, evaluator — are emitted next to run records so a single case is fully reconstructable.

Deterministic by construction

No ambient time/random/datetime.now() in scored paths. Timestamps and seeds are inputs recorded in fixtures or run config. Two runs of the same suite on the same fixtures produce byte-identical artifacts except for an explicit run_id — which is what lets "the injected regression was detected" be a stable test rather than a flaky one.

Open questions / limitations

The scaffold defines the contract; each stage is realized in its milestone. There is no server or persistence layer beyond local files (an optional SQLite trace index is regenerable). See Limitations.
