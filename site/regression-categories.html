Regression categories

A regression fires when a candidate is worse than the baseline by more than a threshold on a dimension. Detection is deterministic and threshold-driven — nothing is learned or fitted. Full rules in docs/REGRESSION_DETECTION.md.

status: taxonomy defined; detector implemented in Milestone 6

Thresholds are the documented defaults; the detector reads them from the suite manifest, so they tune without code changes.

Severity

critical correctness lost (success 1→0, schema valid→invalid, disallowed tool, new unsupported claim). warn quality/efficiency degraded past threshold (latency, cost, partial evidence drop, arg drift). info a noted change that did not cross a threshold.

Application vs. harness noise

Every degradation is attributed app (raises a flag) or infra (recorded, surfaced, but not flagged). A timeout on a flaky mock, a transport error, or a malformed fixture is harness noise. The rule set is conservative — when in doubt it flags as app and labels its confidence — because a missed regression is worse than a noisy one. This is the mechanism behind research question #9.

Controlling false positives

  • Deterministic runs remove sampling variance.
  • Thresholds combine a relative and an absolute minimum, so jitter never fires.
  • Direction-aware: only worse moves flag.
  • Missing cases are reported unpaired, never scored as success.
  • Correlated failures are clustered so one root cause reads as one finding.
