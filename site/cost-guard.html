The cost guard

The one code path in this project that could cost money, and the seven gates in front of it. The guards are the deliverable; the network call is not. The package ships no network client at all.

status: Milestone 11 complete — all five protections (explicit opt-in, dry-run by default, a shared token/cost estimator, a hard max-cost ceiling, a keyed gitignored response cache), plus two the spec did not ask for: a price list that cannot silently authorize spend, and a repository-wide network kill switch. 97 tests; 849 total, all offline

Brief explanation

An evaluation harness gets re-run constantly — after a scorer changes, after a threshold moves, after a report template is edited. None of those is a reason to pay a provider again. And an evaluation harness is exactly the kind of program that gets pointed at a suite of 500 cases by someone who has not read it.

So the question is not "how do we call an API" — that is ten lines — but what must be true before a call is possible, and what the system does when it is about to spend more than you meant. Every decision below follows from answering that in the strictest direction available.

The seven gates

Every call passes through the same fixed ladder (adapters/api_stub.py::ApiAdapterStub.call). The order is the design.

#GateRefusalWhy it sits here
1Opt-inApiAdapterDisabledFirst, so a disabled adapter does not even stat a cache file.
2Cache(returns)Before the budget: a hit spends nothing and must not consume budget, or a completed suite could never be re-run under the ceiling it already paid. Before dry-run: a dry run over a warm cache returns the real answers, free.
3EstimateUnpricedModelReal input tokens; output priced at max_output_tokens. An unpriced model refuses rather than defaulting to a number that looks like a cost.
4Dry run(returns)The default, even once opted in. Nothing below this line executes.
5Verified pricingUnverifiedPricingA ceiling enforced against unchecked prices is theater.
6Max-cost ceilingMaxCostExceededRefuses — never truncates. Checked before the transport, so an over-budget suite makes zero calls, not n − 1.
7TransportTransportMissingAbsent by default. This package ships no network client.

Gates 5 and 6 sit above gate 7 deliberately: budget and pricing are policy, and policy is decided without reference to whether a client happens to be installed. Every refusal subclasses ApiGuardError, which subclasses AdapterError — so the executor's existing adapter-failure handling catches a refused API call the same way it catches a missing fixture. A guard that needs bespoke plumbing to be honored is a guard that will eventually be bypassed.

Deeper technical explanation

Opt-in is a value, not an ambient read

ApiGuard.from_env(env) takes the environment as an argument. Library code that reaches for os.environ makes its behavior depend on a variable no artifact records — the same objection the determinism rule makes to time.time(). The CLI may read the process environment at its boundary; nothing below the boundary does. An unrecognized boolean (LLMREG_API_DRY_RUN=maybe) is refused, not defaulted: a parser cannot know whether the safe fallback for the key it is reading is "spend" or "don't", so refusing both is the only rule that is safe in every position.

LLMREG_API_ENABLED=1 alone buys an estimate, not a call. Turning off dry-run is a second, separate decision, because "I want to use the API adapter" and "I want to spend money right now" are different intentions and one flag cannot tell them apart.

An estimate bounds the cost; it does not predict it

Input tokens are knowable before a call; output tokens are not. The estimator prices output at max_output_tokens — the worst case the API is permitted to produce — because a budget guard that priced the average output is a guard that lets the tail through. CostEstimate.output_tokens_bounded records which of the two any number is, so a report can never present an upper bound as a measurement. The ledger then settles from the provider's reported usage: the guard reasons about what could be spent, the ledger tracks what was.

The ceiling defaults to zero, and refuses rather than truncating

An opted-in adapter with no configured budget can spend nothing at all. The failure mode "I meant to set it and forgot" must cost nothing, so the unset value is the strictest one, not the loosest. And the guard never silently lowers max_tokens to fit a budget: that would change the experiment, and a harness that quietly changes the experiment to stay in budget is worse than one that stops.

The estimator got one home

COST_DECIMALS used to be declared in three modules with a comment asking the reader to keep them in sync. That is survivable while the only consumer is a synthetic price list; it stops being survivable when an estimate is what stands between a run and a bill, because a guard that rounds cost to eight decimals while the evaluator rounds to six is a guard that can be argued with. pricing.py now backs the executor's artifacts, the cost evaluator's metric, the comparison engine's delta, and the guard's ledger. The refactor is byte-preserving: sha256(run.jsonl) for the smoke baseline is still ee23bfde…, the value committed at Milestone 4.

Prices are configuration with provenance

Vendor pricing changes; a constant in a Python file does not. PriceList is loaded from JSON and carries verified (has a human compared these against the provider's published prices?) and priced_at (when?). It is verified: false for every list committed here, because this repository cannot check a price: it has no network, and a number copied into source on the day it was written silently rots. A verified: true list with no priced_at is rejected outright — a "verified" claim with no date cannot go stale, which is the problem.

Estimating and comparing with an unverified list is fine: both sides of a delta use the same prices, so the delta is sound regardless. Spending against one is refused, unless the operator sets allow_unverified_pricing — an explicit statement that they know the ceiling is being enforced against numbers nobody checked.

A transport may not invent a measurement

A response reporting zero tokens, or zero latency, is refused. This is the rule Milestone 10's importers established: a missing measurement recorded as 0.0 is not missing, it is a number, and the comparison engine believes numbers — a zero-latency baseline makes every candidate an unbounded latency_regression. Cost cannot be settled from usage that was never reported either, so the ledger would silently under-count the spend it exists to cap.

The network client that isn't here

adapters/api_transport.py is the seam a real provider client plugs into. It holds a documented reference implementation and nothing imports it: api_stub.py does not, adapters/__init__.py does not re-export it, its import anthropic lives inside the function body, and anthropic is not a dependency of this package.

tests/test_api_stub.py asserts all four by parsing the package's own source with ast, not by watching sys.modules — a runtime check only sees the imports that happened to run in that process. The scanner is itself unit-tested against known-bad inputs (a top-level import, a try:-wrapped import, an if:-wrapped import) so it cannot silently match nothing and make every assertion below it vacuous.

The transport function has no test coverage and never runs in CI, because running it would cost money. It is the documented shape of the thing, not a load-bearing part of the system.

Determinism

Nothing in the guard ladder reads a clock, an RNG, or a socket: stored_at on a cache entry is the run's recorded timestamp, and latency is whatever the transport reports. A live call is inherently nondeterministic — that is a property of calling a real API, not of this code — and it is confined to the transport at the bottom of the ladder, behind all seven gates, in a module nothing imports by default. The perf_counter that measures its latency is imported inside the function body for the same reason the client is: it is the one place where the ambient value is the measurement being taken.

Estimating without any of this

llmreg estimate-cost prices a suite it never runs. It is a calculator: it opts in to nothing, opens no cache, and cannot reach a provider. It exits 1 if the bound exceeds --max-cost-usd, so it can gate a job before the job can spend.

$ llmreg estimate-cost --suite evals/suites/smoke.yaml \
      --pricing config/api_pricing.example.json \
      --model claude-opus-4-8 --max-cost-usd 0.01

suite            : smoke (8 cases)
model            : claude-opus-4-8
pricing          : config/api_pricing.example.json (UNVERIFIED)
                   estimates only; the API adapter refuses to spend against prices nobody has checked
input tokens     : 239 (estimated, ~4 chars/token)
output tokens    : 8192 (upper bound: max_output_tokens)
cost upper bound : $0.205995
max-cost ceiling : $0.010000
within ceiling   : no
api calls        : 0 (this command cannot make one)
result           : FAIL

The ceiling it reports is the one the guarded adapter would enforce, computed by the same estimator — so a number printed here and a number a guard refuses on cannot disagree.

Wiring it up, if you must

from llm_regression_observability.adapters import ApiAdapterStub, ApiGuard
from llm_regression_observability.adapters.api_transport import anthropic_transport
from llm_regression_observability.pricing import load_price_list

adapter = ApiAdapterStub(
    guard=ApiGuard(enabled=True, dry_run=False, max_cost_usd=0.50),
    model_id="claude-sonnet-5",
    pricing=load_price_list("config/api_pricing.json"),  # yours, verified
    transport=anthropic_transport(),                     # requires `anthropic`
)

Four deliberate acts — opt in, disable dry-run, set a ceiling, supply a verified price list — plus install a dependency this project does not declare and pass a transport it does not ship. That is the intended amount of friction.

Open questions and limitations

  • A ceiling is only as good as its price list. It is enforced against chars / 4 tokens times prices an operator supplied. If the price list is wrong, the ceiling is wrong by the same factor, and nothing here can detect that — it has no network. verified/priced_at convert a silent failure into an operator decision; they do not make the estimate correct.
  • allow_unverified_pricing is a real escape hatch. It is off by default and the error text explains the consequence, but it permits spending against numbers nobody checked.
  • The transport is untested by construction. Its Messages-API field mapping is written from the SDK's documented shape and has never been executed against a live response.
  • The network block patches the socket module. A library bypassing it (via ctypes) would not be caught. The guarantee is "no test opens a TCP connection through the standard library", not "no test can possibly emit a packet".
  • A dry-run record marks itself with an infra-origin api_dry_run error because RunRecord has no metadata field. This is a schema workaround; if dry-run records are ever compared for real, RunRecord may want an explicit provenance field.
  • A cache hit is keyed on request content, not on time. A provider that changes a model's behavior behind a stable model id will be served the old response until .api_cache/ is cleared. The right trade for reproducibility; the wrong one for freshness.
