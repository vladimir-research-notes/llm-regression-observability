Results

Every number on this page is produced by a committed, offline, byte-reproducible run. Nothing is illustrative and nothing is rounded by hand. The commands that regenerate all of it are at the bottom.

status: all fourteen milestones (0–13) complete — 18 of 18 injected defects detected with their annotated category and severity; 0 false positives on the 8 negative controls; 19 flags, 16 clusters; the comparison renders as a deterministic, redaction-gated report; each run projects into a span tree and reduces to suite metrics that keep harness signals separate; traces from outside this repository enter through versioned import contracts; the optional paid-API adapter sits behind seven gates and no network client; the ten quality gates of docs/PLAN.md §11 run as one command and exit 0; 956 tests passing, all offline

Everything below is measured on synthetic fixtures with injected defects. Detecting 18 of 18 defects on a suite built to be detected is evidence that the rules fire as specified and that the negative controls do not — it is not evidence of recall on real regressions in real systems, and no such claim is made. Two candidate generators, two purposes. The recorded candidate is the committed fixture — the defect the author wrote, and the oracle's exact referent. re_wrong_source is the instructive one. Splitting "the source is real" from "the source supports the claim" is what makes it visible.

Both re_unsupported_claim and re_wrong_source raise unsupported_claim_count from 0 to 1, and they get different severities. The rule compares claim texts: a claim the baseline never made is an invented fact (critical); a claim that merely lost its support is degraded grounding (warn).

Two of these carry the argument.

  • sj_control_reorder changes final_output and regresses nothing. Every metric is identical on both sides; regression_flags = [] and the summary reads "no regression: final_output changed; no metric crossed a threshold". A regression is a behavioral property getting worse, not a string changing.
  • at_infra_noise has a failed tool call and a red trace, and raises nothing. Its error is origin=infra, so the application is not blamed. That is research question 9, and its cost is a documented masking risk: a real regression co-occurring with harness noise on the same case would be withheld too.

Reproducibility. Two runs on the same fixtures, in separate processes and into different output roots, produce byte-identical run.jsonl, run_meta.json, metrics.jsonl, spans.jsonl, aggregate.json, comparison.jsonl, summary.json, comparison_meta.json, and the rendered report. Each writer re-hashes the file after writing and raises on any mismatch with its in-memory digest. Metric values are rounded at the boundary (six decimals; cost eight), so a score cannot differ in the last bit of a float between platforms.

LimitationsWhat the report cannot see

Three properties, each with a test. Deterministic — no clock, no RNG, no generation timestamp; two renders are byte-identical, and an AST scan fails if any module under reports/ imports time, datetime, random, secrets, socket, urllib, http, or requests. Redaction-masked, then gated fail-closed — free text is masked on the way into the report model, and the rendered document is then scanned for credential-like strings immediately before it is written; one that survived (necessarily in an identifier the redactor will not rewrite) is refused, and the error names the pattern and line without echoing the value. Sourced only from the artifacts — every string is a case id, a metric name, a threshold, or a rule-authored explanation; no model-generated output text is copied into it.

The HTML rendering is one self-contained file: no <link>, no <script>, no <img>, no url(), no external host. A report attached to a pull request should not tell a third party that someone is reading it.

What a span does not claim: the trace records exactly one duration per case, so a child span's width is latency_ms / step_count — a slot, not a measurement. Every span is labeled recorded, derived or none. And spans carry identifiers and counts only: a test scans every span attribute of all 52 committed fixture records against the free text of the record it came from.

Redaction and safety hygiene (Milestone 9)

traces/redaction.py holds the one pattern table and the masking redactor. It runs before the executor hashes a run, before the report generator renders, and before the span writer writes. Twelve rules across two tiers; see Safety.

PropertyResult
Committed fixture records unchanged by redaction52 / 52, all clean
Smoke pipeline byte-identical to before the milestoneyes (run.jsonl, run_meta.json, regression_report.md)
llmreg scan-secrets on this repository0 findings
redaction_status values reachable and tested3 / 3 (clean, redacted, flagged)

The first row is the load-bearing one. Redaction rewrites final_output before an evaluator ever reads it, so a false-positive mask would silently change a score. That all 52 records pass through untouched is what says the rules are tuned for this corpus, and a future rule that starts rewriting scored text fails a test rather than producing evaluator drift.

The three statuses are each reachable, which the schema's vocabulary would otherwise only claim: a clean record stays clean; a credential in final_output yields redacted and [REDACTED:openai_key] in the artifact; a credential in model_id — a join key — yields flagged and the executor refuses the run, naming the field and the pattern without echoing the value.

What is not claimed

  • These are synthetic fixtures with injected defects. Detecting 18 of 18 on a suite built to be detected is evidence that the rules fire as specified, not evidence of recall on real regressions.
  • The eight controls test the specific false positives the fixtures encode (a key reorder, sub-threshold drift, harness noise). They are not a false-positive rate on real traffic.
  • No live model was called. No cost was incurred. Latency is recorded, not measured; cost is estimated under a synthetic price list from a chars / 4 tokenizer.
  • No learned model and no semantic judge scored anything. semantic_similarity_stub and explanation quality are declared placeholders and can never raise a flag.
  • Infra attribution withholds flags on a case whose every error is harness-origin. A real application regression co-occurring with harness noise on that case is masked.
  • The six importers have never met a real emitter. Their shapes are declared here and pinned against synthetic examples.

Three of those would pass just as green in a weaker form, so they are built to fail when they should. smoke_offline enforces offline rather than asserting it: the run scripts execute in a child interpreter whose socket.connect, connect_ex and create_connection raise, so a run that reached for the network fails even on a connected host. redaction proves its scanner is live: an inert scanner reports zero findings on every tree, including one with a key in it, so the gate plants a synthetic credential in a scratch file and requires the scanner to find that before it accepts an empty finding list for the repository. report compares bytes against the committed example — possible only because the report carries no timestamp.

All numbers are produced offline, CPU-only, and are byte-reproducible on the same fixtures. See docs/RESULTS.md and docs/REPRODUCIBILITY.md.

Open questions

  • Detection recall is measured against an oracle the fixture authors wrote. A defect nobody thought to inject is a defect nobody has shown this engine catches.
  • Thresholds are hand-chosen per suite, not fitted. Whether they transfer to a real suite is untested — see Roadmap, direction 1.
  • The scripted adapter's four severity divergences are pinned rather than fixed. Making its injectors match each fixture's recorded defect exactly would remove the divergence and some of the adapter's value as an independent generator.
