Every delta traces to exactly one injected defect: the +250 ms from lc_latency_spike, the dropped tool call from tu_wrong_tool, the added (unsupported) source from re_unsupported_claim, the app error from at_more_retries, the infra error from at_infra_noise. sj_invalid_json and rb_underrefuse change parsed_output rather than a count; sj_control_reorder is a control and changes nothing. The candidate's token totals equal the baseline's because the scripted injectors mutate outputs without re-estimating tokens — a documented limitation of the fixture-derived candidates.

Reproducibility. Two runs on the same fixtures, in separate processes and into different output roots, produce byte-identical run.jsonl and run_meta.json. The executor re-hashes the file after writing and raises on any mismatch with its in-memory digest.

What will be reported

  • Headline — cases, cases regressed, flags by category.
  • Injected vs detected — the scripted adapter injects known defects; this table shows the detector's recall against ground truth.
  • Structured-output validity — baseline vs candidate rate.
  • Tool-call drift — allowed-tool ratio, sequence similarity, missing/extra tools.
  • Evidence grounding — coverage, citation correctness, unsupported claims.
  • Latency / cost — p50/p95 deltas, total cost delta.
  • Refusal behavior — expected vs observed shifts.
  • App vs. harness noise — how many degradations were attributed to infrastructure and excluded from flags.

Reproduction

Steps 1–2 run today; steps 3–4 arrive with Milestones 6 and 7.

llmreg run-suite --suite evals/suites/smoke.yaml --adapter recorded \
    --app-version baseline  --out results/runs/
llmreg run-suite --suite evals/suites/smoke.yaml --adapter scripted-regression \
    --app-version candidate --out results/runs/

llmreg compare --baseline results/runs/<baseline> --candidate results/runs/<candidate> \
    --out results/comparisons/                        # Milestone 6, not yet built
llmreg report --comparison results/comparisons/<id> \
    --out results/reports/regression_report.md        # Milestone 7, not yet built

Without an editable install, use the wrappers python3 scripts/02_run_baseline.py and python3 scripts/03_run_candidate.py; both accept --dry-run to execute and summarize without writing. Generated results/ contents are gitignored and regenerated on demand.

All numbers are produced offline, CPU-only, and are byte-reproducible on the same fixtures. See docs/RESULTS.md and docs/REPRODUCIBILITY.md.
