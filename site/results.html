Results

status: Milestone 6 complete — 18/18 injected defects detected with their annotated category and severity; 0 false positives on the 8 negative controls; 441 tests passing

Everything below is measured on synthetic fixtures with injected defects. 18/18 recall on a suite built to be detected is evidence that the rules fire as specified and that the negative controls do not — it is not evidence of recall on real regressions in real systems, and no such claim is made. See Limitations.

Detection on ground truth (Milestone 6)

Each fixture suite ships an expected.json oracle stating, per case, which regression a correct detector must raise, at which severity, attributed to app or infra. tests/test_comparison.py asserts the engine against it.

Two candidate generators, two purposes. The recorded candidate is the committed fixture — the defect the author wrote, and the oracle's exact referent. The scripted candidate is built at run time by ScriptedRegressionAdapter, which injects one representative defect per category. Its four severity divergences (tu_arg_drift, tu_order_change, re_missing_evidence, re_wrong_source) are a property of that adapter, not a detector failure: it drops a tool rather than drifting an argument, and fabricates a claim rather than dropping a citation. Category recall is 18/18 on both paths, and the divergence is pinned in a test table rather than described.

at_failed_tool is the only case with two flags. Its candidate's compute tool fails (error_rate_regression, warn) and its answer degrades from "done" to "partial" (final_answer_regression, critical). The fixture note says exactly that. Every other defect raises exactly one flag, because a task_success drop is attributed to the category that owns the property that failed — without that rule, all 18 would also report a final_answer_regression.

The three rows that carry the argument

  • lc_latency_spike scores task_success = 1 on both sides. The answer is correct and byte-identical; only the process got slower (150 → 420 ms). A string-diff test sees nothing. The engine raises latency_regression.
  • at_infra_noise has a failed tool call and a red trace, and raises nothing. Its error is origin=infra, so the application is not blamed. The case is named in comparison_meta.json under infra_attributed_case_ids, not dropped — research question 9.
  • sj_control_reorder changes final_output and regresses nothing. The JSON keys were reordered; every metric is identical on both sides. A regression is a behavioral property getting worse, not a string changing.

Three rows carry the argument of this project:

  • lc_latency_spike scores task_success = 1 on both sides. The answer is correct and identical; only the process got slower. A string-diff test sees nothing. The latency percentiles see +65 ms at p95.
  • at_infra_noise scores task_success = 1 and app_error_count = 0 on the candidate, despite a failed tool call and a red trace. The error is origin = infra, so the application is not blamed — research question 9.
  • sj_control_reorder moves nothing. The raw JSON string changed (keys reordered); every metric is identical on both sides. A regression is a behavioral property getting worse, not a string changing.

The remaining five cases each move exactly the metric their injected defect targets, and no other. tests/test_evaluators.py asserts the full metric map for all 26 cases of the six fixture suites × both sides, against exact literals.

Reproducibility. Two runs on the same fixtures, in separate processes and into different output roots, produce byte-identical run.jsonl, run_meta.json, metrics.jsonl, comparison.jsonl, summary.json, and comparison_meta.json. Each writer re-hashes the file after writing and raises on any mismatch with its in-memory digest. Metric values are rounded at the boundary (six decimals; cost eight), so a score cannot differ in the last bit of a float between platforms.

Test status

python3 -m pytest -q → 441 passed, CPU-only and offline (6 scaffold + 8 smoke + 54 schema + 25 fixtures + 46 adapters + 51 executor + 155 evaluators + 96 comparison).

What is not claimed

  • These are synthetic fixtures with injected defects. 18/18 recall shows the rules fire as specified, not recall on real regressions.
  • The eight controls test the specific false positives the fixtures encode (a key reorder, sub-threshold drift, harness noise). They are not a false-positive rate on real traffic.
  • No live model was called. No cost was incurred. Latency is recorded, not measured.

Reproduction

Steps 1–4 run today; step 5 arrives with Milestone 7.

llmreg run-suite --suite evals/suites/smoke.yaml --adapter recorded \
    --app-version baseline  --out results/runs/
llmreg run-suite --suite evals/suites/smoke.yaml --adapter scripted-regression \
    --app-version candidate --out results/runs/
python3 scripts/04_score_runs.py                      # -> results/processed/

llmreg compare --baseline results/runs/smoke-baseline-recorded \
    --candidate results/runs/smoke-candidate-scripted-regression \
    --out results/comparisons/                        # add --fail-on critical for CI

llmreg report --comparison results/comparisons/<id> \
    --out results/reports/regression_report.md        # Milestone 7, not yet built

Without an editable install, use the wrappers python3 scripts/02_run_baseline.py, 03_run_candidate.py, 04_score_runs.py and 05_compare_runs.py; all accept --dry-run to execute and summarize without writing. Generated results/ contents are gitignored and regenerated on demand.

All numbers are produced offline, CPU-only, and are byte-reproducible on the same fixtures. See docs/RESULTS.md and docs/REPRODUCIBILITY.md.
