Integration contracts

A trace produced outside this repository enters through an importer, which maps it onto RunRecord. Everything downstream — evaluators, comparison engine, span projection, report generator — runs over the result unchanged. Adding a source is: write a TraceImporter, register it. Nothing else moves.

status: Milestone 10 complete — a versioned envelope (contract 1.0), six importers, llmreg import-trace / llmreg export-run, and an end-to-end demonstration in which two imported code-agent sessions are compared by the unchanged engine (2/2 injected defects detected, 0 false positives on the 2 controls); 101 tests in tests/test_integration_contracts.py

No sibling repository is required, present, or read. The five external trace shapes below are declared by this repository and pinned against committed synthetic examples under data/external/. That is a contract, not a reverse-engineered dump: if a real emitter differs, the importer is the single place the difference is absorbed, and its example fixture is where the disagreement becomes a test failure instead of a silent mis-score.

Brief explanation

Everything before Milestone 10 assumed a trace was produced here, by an adapter this repository owns. That assumption is what the framework has to give up to be useful to anything else. Milestone 10 defines the contracts by which a foreign trace crosses the boundary — and deliberately does not depend on any of the systems it defines them for.

Deeper technical explanation

The envelope (contract 1.0)

A bundle this repository exports is a TraceBundle. It makes four claims an importer can check before reading a single record:

FieldClaim
contract_versionwhich version of this envelope. An unknown version is refused, not guessed at.
source, source_schema, source_versionwhich system emitted the payload, under which of its schemas. Only that system's importer may read it.
record_schemaa fingerprint of RunRecord at export time — 7c781c9c2fad.
payload_sha256digest of the payload's canonical JSON. A bundle edited after export does not verify.

The fingerprint is derived from the dataclass, not declared. A hand-maintained version constant is the one nobody remembers to bump; this one changes the moment a field is added, removed or retyped, and the test suite pins the current value. A bundle whose fingerprint differs from the reading build's is refused in strict mode: every downstream score would otherwise be computed against a shape the exporter never wrote.

exported_at is a recorded input. export_bundle() requires one and reads no clock, so two exports of one run are byte-identical — without which payload_sha256 would be useless as a change detector.

Bare documents, and spans

A sibling system will not wrap its traces in our envelope, and demanding that it does would make the contract useless for its purpose. A bare source document imports exactly as well, minus the four claims, provided the caller names the source. Sniffing a shape to identify it is guessing precisely where guessing costs the most, so it is not done.

Spans are not in the payload. observability/spans.py derives a span tree from (EvalCase, RunRecord, metrics) as a pure projection; shipping spans would ship a derivation the receiver can recompute and cannot verify. An imported record projects into a valid span tree for free, and a test proves it without any importer knowing what a span is.

The four rules an importer obeys

Mapping two vocabularies onto each other is where evaluation harnesses quietly start lying. The contract is defined by what an importer may not do.

1. It may not drop a field in silence

Every key of a source document is mapped, listed in the importer's ignored_fields (a deliberate, documented drop — a chat transcript, a workflow id), or unknown. An unknown key is a field the source grew after the importer was written: in strict mode it raises; with --lenient it lands in unknown_fields and in a warning. It never simply disappears. Strict-by-default is the right trade for an evaluation framework — you want to know a field appeared before you score against it.

2. It may not invent a measurement

A missing latency_ms imported as 0.0 is not missing data. It is a number, and the comparison engine believes numbers:

relative(0.0, 300.0) == -1.0          # zeroed candidate: "100% faster". No flag.
relative(300.0, 0.0) == float("inf")  # zeroed baseline: unbounded latency_regression.

So a record with no recorded duration is refused in strict mode with that sentence, rather than scored. claude_api is the source whose natural shape tempts an importer into inventing one: the API response carries tokens and a stop reason, and the client is what held a stopwatch. Cost is different and is not refused — the executor's CostModel prices it, and a comparison across two price lists is already disabled.

3. It may not guess an attribution

app versus infra is this repository's distinction (research question 9), not a field any external system emits. Each importer publishes an error_origins table; an unmapped kind resolves to app and warns. That direction is deliberate: infra withholds regression flags, so defaulting there would let an unrecognized error silently suppress a real regression. A false flag gets investigated; a silent suppression does not.

4. It may not import a secret

Milestone 9 observed that redaction_status="flagged" is unreachable on a trace this project wrote — the executor refuses to persist one — and named the import boundary as where it becomes reachable. It does, here. Content is masked in place and the record is marked redacted; a certain-tier match in an identity field (a case_id, a model_id, a tool name) is flagged, and the import is refused naming the field and the pattern, never the value. There is no safe repair: masking a join key corrupts every downstream comparison, and keeping it writes the secret to disk.

The six importers

SourceWhat it isLoses
llmregthis repo's own export; the identity mapnothing (round-trip tested)

claude_apirecorded Messages-API responsesthinking blocks, message/tool ids

llmreg is the reference implementation. It is the only importer that can be lossless, so it is the only one whose round trip is a meaningful test: import(export(records)) == records, byte for byte. The five foreign importers each lose something, and each says what.

Three mappings worth naming

  • code_agent_runtime: tool order ignores messages. order_index is a tool's position among tool calls, not among steps. The tool evaluator diffs sequences of tools, and a message the agent emitted between two of them is not a gap in that sequence. And agent_version becomes tool_version, because a code agent's tool surface ships with its binary — calling it a prompt version would be a lie no test could catch, since both are opaque strings.
  • bioagentbench: seconds are not milliseconds. wallclock_seconds is multiplied by 1000. A unit mismatch is the quietest, most expensive bug an importer can have: it does not raise, it does not look wrong, and it silently turns a 420 ms answer into a 0.42 ms one — a latency improvement of three orders of magnitude against any baseline.
  • agent_control_bench: the decision has a source. response.refused lands in parsed_output, which is where refusal_decision() looks first. Failing that it falls back to a lexical scan of the answer text — and records which it used. An import that loses the label therefore degrades visibly, into decision_source="lexical_fallback", rather than silently into a guess.

An imported trace, end to end

evals/suites/external.yaml names four cases drawn from the committed fixture suites. That reuse is the point: an external system that runs your evaluation cases hands you traces keyed by your case ids, and comparing them against your baseline is the reason an import contract exists.

llmreg import-trace --source code_agent_runtime \
    --input data/external/code_agent_runtime/baseline.json \
    --suite evals/suites/external.yaml \
    --app-version external-baseline --run-id ext-baseline --out results/runs

llmreg import-trace --source code_agent_runtime \
    --input data/external/code_agent_runtime/candidate.json \
    --suite evals/suites/external.yaml \
    --app-version external-candidate --run-id ext-candidate --out results/runs

llmreg compare --baseline results/runs/ext-baseline \
               --candidate results/runs/ext-candidate --out results/comparisons

llmreg report --comparison results/comparisons/external-external-baseline-vs-external-candidate \
              --out results/reports/external_regression_report.md

Or in one step: python3 scripts/09_import_external_trace.py.

The candidate session carries two injected defects — a disallowed shell_exec call, and a retried search — and two unchanged control cases. The unchanged comparison engine, with the same thresholds the smoke suite uses, finds:

Why an import is executed, not written

An imported trace could have been written straight to run.jsonl. It is not. ImportedTraceAdapter is a ModelAdapter whose behavior is a record somebody else recorded — exactly as RecordedModelAdapter replays a committed fixture — and it is handed to the ordinary execute_suite(). That buys, unchanged: identity re-stamping, redaction before accounting, token estimation and cost pricing where the source carried none, and records_sha256 over the bytes actually written. A second artifact writer would be a second place those five decisions are made, and the two would drift.

import_meta.json

Written next to run.jsonl. run_meta.json says what the run is; this says what the import could not say — warnings, ignored fields, unmapped fields, absent fields, and which cases the source supplied a task definition for. A comparison that reads clean over a trace half of which never arrived is exactly the lie an evaluation framework must not be able to tell quietly, so the losses are an artifact rather than somebody's terminal scrollback.

Open questions and limitations

  • The five external shapes are declared here, not observed. No sibling repository was read. Each importer is a hypothesis about a shape, validated against a synthetic example this repository wrote. First contact with a real emitter will move some of these tables; the four rules are what should survive.
  • ignored_fields is documentation. The mechanical check is per-call-site. A key deliberately ignored at one path is still unknown at another — which is the behavior you want, but it means the published list and the code are kept in step by review, not by a compiler.
  • A lenient import can score a zeroed latency. --lenient exists so a source with no duration is usable at all; it does not make the resulting latency comparison meaningful. import_meta.json names latency_ms in absent_fields, and the operator has to read it.
  • Nothing validates a source's own semantics. If bioagentbench reports wallclock_seconds that are actually milliseconds, the importer multiplies by 1000 and nothing notices. A contract can pin a shape; it cannot pin a meaning.
  • One suite per import. An imported document must cover exactly the cases the named suite defines — no more, no fewer. A trace answering a superset is refused rather than silently subsetted.

See Limitations and Safety. The optional paid-API adapter — dry-run mode, cost estimator, hard max-cost guard, response cache, explicit opt-in — is Milestone 11; the claude_api importer here reads recorded documents and never calls an API.
